# Harness 启动菜单

独立于 Harness 安装的本机启动管理器。双击 `launch.vbs`，或使用桌面和 Windows 开始菜单中的「Harness 启动菜单」。使用 Harness 自带 Python 及 Edge 应用窗口；没有 Edge 时使用默认浏览器。无需安装第三方依赖。

- 自动扫描 desktop profile 的已安装 bundle，支持 scoped 包和本地链接包。
- 逐项勾选、搜索、全选、全部关闭、当前配置、自定义方案。
- 保存/覆盖/删除方案，导入及导出方案 JSON。
- 「启动 Harness」应用选择后启动；「应用选择 / 还原为原生」只切换，不启动。
- 修改前自动备份、可恢复历史 package.json，启动失败自动恢复配置。
- 检测 Harness 进程，运行中拒绝修改配置，不自动结束进程。
- 官方两个基础 bundle 始终保留，账号、会话、依赖和 YAML 配置均保留。
- 更换应用及数据目录；开启配置、备份、程序目录。

默认应用：`<Harness 安装目录>\DeepSeek Harness.exe`。默认数据目录：`DSH_HOME`，未设置时为 `%USERPROFILE%\.dsh`。

管理器设置、备份和日志位于 `%LOCALAPPDATA%\HarnessLauncher`；管理器源码位于 `<启动管理器源码目录>`，不放在 Harness 更新目录中。

「原生模式（全部关闭）」会同步已适配插件的磁盘补丁。目前内置 dsh-purge 适配器：

- 首次核验保留的官方 app.asar（包括归档内置完整性信息）并记录版本、哈希。
- 关闭时把 resources/app 暂存到安装内独立目录，使用官方 app.asar；插件提示词、已识别的注入规则、红队预设和 CLI 路径一起还原。
- 重新启用时恢复捕获的同版本补丁目录及注入文件，不重新执行会修改其他安装的补丁脚本。
- 账号、会话、插件依赖和普通偏好均保留；原生模式不是清空用户数据。
- 任一步骤失败会回滚；操作前写入恢复日志，中断后下次切换会先回滚未完成操作。
- 应用或插件升级、文件被外部修改、目录冲突、无官方归档时，停止覆盖并报告原因。不会将旧补丁套在新应用上。升级后需要在当前版本重新应用插件并建立新的快照，保留旧快照以便核查。
- 没有安装前记录的新插件不会被假定为无补丁。通过「安装与自动记录」完成登记后，可按文件差异自动管理；未记录插件或还原后仍有手动 YAML 插件条目/动态表达式时，拒绝保证原生模式。

补丁状态和文件快照存放于 %LOCALAPPDATA%\HarnessLauncher\patches；暂存目录为安装的 resources/.harness-launcher-* 及数据目录的 .harness-launcher-*。不要手工删除这些目录，它们可能保存当前未激活的官方归档、插件目录和预设。

新安装插件后点击「刷新列表」；被关闭的插件仍保留在 node_modules / dependencies 中，下次仍可发现。启动顺序沿用已有 bundle 列表，新启用的 bundle 追加到列表末尾。新增插件的兼容性和相互依赖仍由插件和 Harness 负责。

菜单仅监听 `127.0.0.1`。每次服务启动使用随机访问令牌，关闭所有菜单窗口约 5 分钟后服务退出。双击快捷方式可重新打开；重复打开会复用已运行服务。不会把访问令牌写入日志，默认不读取账户凭据和会话文件。

## 开发验证

```powershell
python -m unittest discover -v
```

移除管理器前，先选择要保留的模式并点击应用；不要删除仍保存非激活版本的 .harness-launcher-* 暂存目录或 patches 快照。删除启动菜单快捷方式和源码本身不会回滚应用文件。


## 通用安装与文件记录

1. 安装前打开「安装与自动记录」，填写准确的插件包名。
2. 安装来源可填写 npm 包名、本地路径或 HTTPS 地址。菜单先建立快照，再通过官方 dsh CLI 安装；也可留空，在快照完成后自行安装。
3. 点击「启动并测试插件」，仅测试这个新插件，应用它自身的补丁。完全退出 Harness（含托盘）后点击「扫描差异」。
4. 复核记录窗口内的新增、修改、删除清单，确认归属后保存。保存后无须编写插件专用适配器；关闭按相反安装顺序撤销，启用按安装顺序恢复。
5. 已有自动记录的插件升级时，在记录列表点击「升级 / 重新记录」，填写新版来源（例如 npm 包名及版本），也可留空后自行升级。开始时先撤销旧层并建立新基线；安装与测试完成、确认差异后才替换当前记录，旧版本和差异索引保留。新版不再写入的旧文件不会沿用。复核期间版本再次变化会要求重新扫描。未记录的旧插件不能凭安装后的快照补回未知历史改动。
6. 必须在升级前开启记录；绕过菜单升级、运行后新增的记录外补丁或外部修改会触发保护，不能自动推断或保证还原。dsh-purge 仍使用已有内置适配，版本升级不属于通用重录入口；Harness 本体升级也需要重新校验官方基线。

记录是时间窗口内的文件差异，不是进程审计：同时改其他文件或安装多个插件，可能无法准确归属。其他插件版本同时变化会拒绝登记，清单仍需复核。

默认范围：当前安装的 resources/app、app.asar、app.asar.bak、app.asar.unpacked、runtime/cli，以及当前数据目录的 AGENTS.md、CLAUDE.md、prompt-inject.md、rules、skills、.agent-presets 和 desktop 的两个 cordis YAML。目录中的链接只记录目标，不跟随读取外部路径；新增/修改链接或文件/目录类型互换会拒绝自动登记。

默认排除账户凭据、会话、附件、缓存、profile/node_modules 和 package/lock 安装元数据。插件依赖仍保持安装，由启动菜单控制 bundle；不会因关闭插件而卸载依赖。

不覆盖注册表、系统服务、驱动、网络端的更改、其他安装及范围以外的目录。自动记录不等于整台电脑的系统还原。

共享文件会检查基线哈希，不强行合并。若某插件是在另一个补丁插件的文件基础上记录的，可能必须联动选择原有基础组合，或在新基线上重新记录。完全关闭可按相反次序撤销独立/可叠加层。

保存后会记录托管范围的目录指纹；窗口外发生新变化时，停止自动覆盖。首次建立快照需要保存源文件，可能较慢，后续复用未变化内容。后台任务进度可查看，关闭菜单也不取消正在执行的官方安装器。中断日志和快照保存在 patches/<安装与数据目录标识>/tracking，勿手动删除。
