# 0.3.2 目录检查点设计

状态：0.3.2 完成完整回归及本机约 30 秒目标验证；8 个场景完整界面观察上界为 18.003–31.763 秒，不保证严格 30 秒。见[验证记录](validation-0.3.2.md)。

## 问题与设计依据

purge 将官方 ASAR 完整解包；当前安装有 12,969 个普通文件，其中与官方归档相同的有 12,912 个。这不是每次开关新增一份缓存。现有内容寻址存储已经记录官方基线、插件差异及组合快照，主要耗时来自反复确认工作目录没有被外部修改。

借鉴 Git 的对象库、索引及文件系统监视机制：对象库保留内容，索引保存已验证状态，变更来源决定哪些状态必须重新验证。不能仅保存增删改数量，也不能用 `assume-unchanged` 或文件大小、修改时间代替检测。[Git 索引文档](https://git-scm.com/docs/git-update-index)

## 选择的方案

1. 保留现有官方基线、SHA-256 内容对象、插件前后差异、组合清单及可恢复事务。
2. 为大型目录建立可丢弃检查点：相对路径、类型、内容哈希、文件身份集合、卷标识、USN 日志标识及连续游标。
3. 首次建立时完整扫描和内容验证；每个普通文件必须在独占的数据读句柄内取得有效 NTFS 身份，排除数据写入，并用 `FSCTL_WRITE_USN_CLOSE_RECORD` 结束遗留属性句柄导致的 USN 合并周期；目录和链接在读取前也建立关闭记录屏障。扫描期间不能有其他相关变更。没有这些证据就不建立检查点。独占句柄自己读取字节，不另开文件。
4. 使用卷根目录句柄读取非特权 USN 日志。不要求管理员权限，不创建、清除或调整系统日志容量；首次建立检查点时为受管文件提交 USN CLOSE 记录，不修改文件字节。非特权记录可能隐藏名称，因此按文件 ID 和父目录 ID 检测变化。
5. 日常读取连续日志，只要相关目录没有改变，就复用已验证目录。顶层目录单纯重命名不改变内容，核对目标目录身份后可以复用。任何内部新增、删除、修改、重命名、硬链接、重解析点或安全属性事件均使该目录检查点失效。
6. 此版本遇到目录内部变化时重新完整验证该目录，避免把复杂的路径重命名、硬链接和并发写入处理带入关键回滚路径。启动器的常规 purge 切换只搬移同一目录，仍能走快速路径。
7. 对已验证目录复用路径对象、父子索引和目录指纹，每个目录最多保存两个位置，适用于活动目录和暂存目录。每次复用仍重新验证目录身份和连续日志；预演视图拿到独立的条目及子目录集合，虚拟改动不能回写检查点。纯路径字符串语法检查另有 32,768 项内存上限，不涉及磁盘状态。
8. 切换后的元数据索引直接来自刚刚独立验证通过的完整快照，不再重复枚举整个目录。验证后出现的外部改动不会被当作可信状态吸收，下次检查仍会发现。

## 稳定性边界

| 情况 | 处理 |
| --- | --- |
| 日志滚动、被重建、接口不可用、返回记录未知或损坏 | 丢弃加速结果，走原完整校验 |
| 程序重启 | 持久化格式 3 检查点只有在日志标识及游标连续时才可复用；缺少完整变更证据的格式 1、2 作废 |
| 同大小修改并恢复 mtime | USN 数据写入事件使检查点失效 |
| 文件仍有数据读写句柄 | 不建立检查点；即使写句柄已关闭，遗留读句柄也可能使后续同类写入不产生新事件 |
| 整个目录换成其他目录、链接或挂载点 | 核对卷与文件身份，保留祖先链接检查 |
| purge 开关造成整目录搬移 | 同一目录身份、仅顶层重命名事件时复用 |
| 切换失败、进程启动失败、断电 | 使用原不可变内容对象和持久化事务恢复；缓存不参与回滚决策 |
| 缓存损坏、丢失、容量超限 | 重新校验；有上限且同一身份只保留一个目录版本 |

实际复现还发现：属性读取句柄不受数据独占共享模式限制，也能保留合并周期。修订后的首次校验使用 Windows 的 [USN CLOSE 记录接口](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_write_usn_close_record)，只过滤本次建立屏障返回的确切 USN；其他事件仍使检查点失效。接口失败时不建立检查点。

USN 只记录变化事实，不能用来回滚。一个写句柄的多次同类写入可能合并，因此不能在存在数据读写句柄时建立检查点，也不能只等待 CLOSE 事件。[Windows 变更日志语义](https://learn.microsoft.com/en-us/windows/win32/fileio/change-journal-records)

## 快速连续改写与文件缓存

首轮 GitHub CI 发现：快速连续改写可能拥有完全相同的修改时间与 ChangeTime，不能只把高精度时间字段当成内容变化证据。文件缓存格式 3 因此同时检查当前日志身份和[文件最后 USN](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_read_file_usn_data)。新哈希进入缓存前强制结束旧变更合并周期，并以关闭屏障之后的 USN 保存；普通命中不额外生成关闭记录。日志重建、接口不可用或关闭屏障失败时不建立新的可复用条目。目录检查点也升级为格式 3，避免沿用旧文件缓存曾提供的内容。

回归通过固定时间字段、保留真实 NTFS 变更序号和遗留属性句柄，稳定复现时间戳碰撞；同时覆盖日志身份变化与关闭屏障失败。没有给测试增加延时或放宽内容正确性断言。

## 备选方案

- 仅文件系统通知：事件可能延迟或溢出，无法独立证明跨重启连续性，不作为跳过校验的依据。
- 重新打包补丁 ASAR：可能降低文件数量，但涉及 Electron 路径、原生模块和插件兼容性迁移，本次不改变运行布局。
- 删除回滚文件：不减少活动解包目录的文件数，反而损害恢复能力，不采用。

## 验收

先覆盖日志解析、日志断档、目录替换、跨目录搬移、同大小修改、未关闭写入、文件增删、硬链接和缓存损坏，再跑现有切换及故障恢复测试。真实计时从启动请求开始到窗口可用，覆盖原生、whale、purge 和双插件的日常启动及切换。首次建立检查点和实际外部文件变化可慢；常规切换不能归入此例外。
