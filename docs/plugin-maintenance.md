# 插件更新、卸载、恢复与缓存清理

适用版本：当前开发版本。[返回首页](../README.md)

## 从哪里开始

打开左侧“更新与卸载”，点击“检查插件更新”。这一步只查询版本，不安装、不切换插件。查询结果缓存 5 分钟；日常启动不会联网检查更新，也不会运行缓存清理。

带“…”的按钮先打开确认页，此时**尚未执行**。确认页说明将修改什么、保留什么；点击“取消”或关闭窗口都不会执行操作。

| 入口按钮 | 确认后才执行的操作 |
| --- | --- |
| 更新到指定版本… | 点击“确认更新”才保存检查点并安装目标版本 |
| 重新验证当前版本… | 点击“确认重新验证”才重新安装并验证同一版本，不表示升级到了新版 |
| 卸载插件… | 点击“确认卸载”才还原已记录补丁、移除插件及加载配置 |
| 清理缓存… | 点击“确认清理缓存”才删除清单中的无引用缓存；没有候选时不可执行 |
| 恢复此检查点… | 点击“确认恢复”才还原检查点 |

详细文件清单默认折叠，可按需展开。缓存页会先显示可清理数量和预计释放空间。

| 安装来源 | 查询和升级行为 |
| --- | --- |
| 公共 npm 包 | 查询 latest，比较 SemVer，执行时固定到具体版本；不自动选用预发布或弃用版本 |
| GitHub 分支 | 查询提交和 package.json，预览显示明确来源，安装固定到提交；不能证明本机提交时不声称“确定过期” |
| 已固定 Git 提交 | 保持固定版本，提示手工核实，不擅自跟随分支 |
| 本地 file/link | 外部源目录保留；只有仓库身份对应时才提供明确改用 npm 的选项，npm 查询失败可检查包内声明的 GitHub 仓库 |
| 私有注册表、别名、其他压缩包 | 保留原来源，提示人工处理，不替换为公共 npm 同名包 |

查询结果不是兼容性认证。执行前重新读取精确目标的包信息，安装后核对实际版本，并再次核验其他插件和共享依赖。

**组合建议：** dsh-purge 等修改宿主代码或全局提示词的插件建议单独启用，尤其在首次安装、升级和排查问题时；官方基础组件保持开启。这样可减少插件间冲突、便于定位问题，但不能排除插件自身或官方版本兼容性问题。这是一项使用建议，不会强制取消其他插件的勾选，也不替代文件校验和回滚。确需组合使用时，应逐个加入其他插件并验证，保留可恢复的检查点。

## dsh-purge 专用适配器

**为 dsh-purge 专门适配，把启用补丁和回到官方原生放进同一套操作流程。** 针对它会修改宿主代码、提示词、预设和 CLI 的特点，启动器内置专用适配器，统一管理已记录补丁的启停、校验与回滚。

完成当前宿主上的首次运行记录与验证后，完全退出 Harness，选择插件开关，再点击“启动 Harness”或“仅应用，不启动”，即可同步补丁状态。关闭后保留可再次启用的补丁及恢复记录，账号、会话和附件不纳入切换范围。

- **恢复有依据：** 原生文件以当前宿主的安装前检查点为准，切换时核对官方归档与受管文件，避免旧版备份覆盖新版程序。
- **专用适配与通用机制协作：** 适配器处理宿主解包树、提示词和预设，YAML 等其他受管修改使用通用差异记录；共同使用内容去重存储与事务回滚。
- **冲突保留现场：** 官方版本变化、记录之外的用户修改或补丁冲突会停止覆盖，保留检查点供核查；官方更新后需要重新验证当前版本的补丁。

已实测 **dsh-purge 1.1.90 + Harness 0.2.1-rc.5** 的两轮启用、关闭与官方原生恢复，原生程序、归档和 CLI 校验一致，248 项受保护内容无变化。[完整验收与耗时记录](purge-source-audit.md#当前安装的-rc5-启停与原生回退验收2026-11-03)列明测试范围；此结果不代表所有插件组合、未来版本或 purge 自带重启流程都已通过验证，也不代表窗口可用时间已达到 30 秒。

## 可恢复升级

1. 完全退出 Harness，点击目标插件的“更新到指定版本…”。查看目标版本、来源和保留范围。
2. 确认后，检查宿主、插件及补丁，按内容去重保存维护前检查点；暂时关闭插件，调用 Harness 自带的包管理器安装精确版本。
3. 启动器打开仅加载目标插件的首次运行环境。正常使用新版；purge 需要先按其界面应用补丁。
4. 完全退出 Harness，回到“更新与卸载”，点击“完成首次运行验证”。校验通过后保存新差异、恢复原启用组合，并保留旧检查点。
5. 如需回退，退出 Harness，在“恢复点”中先预览再恢复。

普通插件使用安装前后文件差异；purge 使用宿主补丁记录，验证旧解包树、规则和预设后还原原生，再捕获当前宿主上的新版补丁。`dshTarget` 缺失或不同不再直接阻止安装，也不表示已经确认兼容。官方安装器的检查、首次运行、宿主身份、其他插件与共享依赖、可逆文件记录仍必须通过；失败保留检查点并提供恢复入口，不覆盖旧宿主记录。

官方更新后暂停的普通插件，即使当前已经是最新版，也可在检查更新后点击“重新验证当前版本…”。固定到 Git 提交的暂停插件只重新验证原提交，不自动跟随分支。验证完成后解除暂停；没有通过的插件不会被标记为升级成功。

维护窗口显示阶段进度条、耗时和已处理文件数。文件总量或包管理器下载总量未知时显示活动条，不能把它当作下载百分比；安装结束后继续显示“等待首次运行与退出验证”，直到最终记录保存。

包文件、依赖包与恢复副本分别显示校验子步骤。较大的文件集合最多使用 8 个工作线程；每个文件仍独立检查内容与读取期间的变化，任一失败都会停止完成登记。相同 SHA-256 内容复用已有副本，避免为重复检查创建临时文件和重复落盘。此优化适用于所有插件，不按包名放宽条件。

更新页与执行流程共用短期查询缓存，但执行前仍重新读取固定目标的元数据。网络或证书错误会保留其真实原因，不再误报“目标版本变化”。Windows 公共元数据重试使用系统证书验证，拒绝未知主机、凭据和重定向；不关闭 HTTPS 校验。

维护中禁止普通启动和切换，避免绕过未完成的验证。首次检查、下载和维护恢复可能超过 30 秒；约 30 秒目标针对完成记录后的日常启动与组合切换。

确认自动安装或升级时，也授权所选固定来源的安装脚本。npm 来源使用精确版本授权键；GitHub 来源使用包含完整提交的实际下载地址。通过官方安装器的 `--allow-build` 传递，不使用通配符或放行全部依赖。本机 pnpm 11.28.5 对 Git 来源要求来源授权，单独的包名不足以授权构建。授权保存在当前 profile，维护检查点包含该策略文件；其他依赖继续使用原有策略。无法确认来源的本地目录不获自动构建授权。[pnpm 官方构建授权说明](https://pnpm.io/settings/build#allowbuilds)。

安装、升级和卸载时，启动器会暂时禁止**非目标插件**执行构建脚本，操作结束后恢复这些插件的原策略；目标版本的精确授权和安装器新增的其他正常配置会保留。这样维护一个普通插件时，不会顺带执行另一个插件的安装补丁脚本。此机制按安装清单工作，不依赖特定插件名称。新依赖仍遵循已有构建策略，不自动全部放行。策略出现冲突、无法确认隔离能力，或安装进程仍未退出时，停止继续处理并保留恢复点。

## 卸载插件

点击“卸载插件…”先查看确认页，列出目标插件记录内需要还原或移除的文件，并说明保留内容。此时插件仍保留，只有点击“确认卸载”才执行；取消不会卸载。执行时重新验证确认页内容、插件代码与受管文件。停用插件也会检查其代码和暂存补丁，不能把后来加入的用户文件当成缓存删除。

卸载先还原已记录补丁，再用官方包管理器移除包和加载配置。其他插件显式依赖目标包、存在未记录插件、补丁层依赖或内容冲突时停止。其他顶层依赖及其递归依赖图会被固定；包管理器改动共享依赖时，不报告成功，保留恢复点。

外部本地插件源目录只移除配置中的引用和 node_modules 链接，不删除源目录。回退前再次验证外部源没有变化，恢复 Windows junction 时规范化系统路径前缀。

从外部本地来源升级到已确认的下载包时，保存检查点后先验证并移除原目录链接，再调用官方安装器；避免 Windows 包管理器尝试覆盖 junction 或沿链接清理源码。失败时恢复原链接。恢复中断后不会穿过已恢复的链接检查已删除的包内文件。

## 校验和恢复边界

- 保留账号、会话、附件、工作区；它们不纳入维护删除范围。对已记录规则、提示词等受管文件，后来编辑导致内容不符时停止覆盖。
- 检查点覆盖受管应用文件、规则/预设/YAML、插件代码与依赖、固定包管理元数据及启动器控制记录。任意安装脚本写入外部服务、注册表或其他目录，不属于可恢复范围。
- 宿主补丁插件也使用通用文件差异记录：专用层负责解包应用、提示词和预设，其余受管修改（例如 profile 的 YAML 注入）与普通插件一样随开关恢复。原生内容以本次安装前的检查点为准，避免插件遗留的旧版备份覆盖新版官方文件；不重复存储整份解包目录。
- 文件内容按 SHA-256 存储一次，清单引用内容对象。恢复逐项验证，只删除已验证的叶子和空目录，不递归删除未知目录。
- 官方更新后的独立记录继续引用共享内容库，不为新宿主再复制一套恢复文件。应用指向官方运行时的目录链接只记录链接本身，不沿链接重复扫描或备份；恢复前检查目标范围，拒绝越界目标和链接套链。
- 升级或卸载失败且能稳定校验现场时，保存失败状态，可从预览恢复。恢复中断后可识别已经恢复的条目并继续。
- 检查点之后出现未知改动、首次运行尚未封存的新文件、宿主被更新或原始外部源被修改时，自动回退会停止并保留材料。不能保证任意安装脚本崩溃后都能无条件一键回滚。
- 维护时声明 `maintenance-transaction` 能力，旧启动器不能继续处理该事务。请在建立事务的版本中完成验证或恢复。

官方更新的原生、带插件及混合状态处理见[更新边界](host-updates.md)。本版本不自动把旧补丁三方合并到新版 Harness。

## 无引用缓存清理

点击“清理缓存…”查看数量、预计释放空间和详细清单；点击“确认清理缓存”后才删除，取消不会清理。清理使用引用标记和回收：当前组合、插件历史、原生基线、配置备份、保存方案和维护恢复点都作为保留入口，递归遍历内容对象引用。只有无引用、合法命名且超过 1 小时的对象才进入候选。

执行前在维护锁内重新计算引用和候选，预览变化则要求重新预览；删除前验证对象内容。引用缺失或对象损坏时停止。它不清理 pnpm 全局缓存、共享依赖、外部源目录、其他安装的数据，也不按时间删恢复历史。保留历史仍引用的对象不会回收，因此反复操作后不承诺磁盘占用归零。

统计先枚举本次缓存目录中的对象名称，再分析引用，避免把官方文件清单里每一个未缓存的哈希都拿去反复访问磁盘。读取引用对象和删除候选时仍检查路径与内容；枚举之后新出现的对象不进入本轮清理，确认执行时重新计算。

清理按需执行，不在每次启动时扫描；校验缓存原有的条数上限和旧身份淘汰机制继续保留。
