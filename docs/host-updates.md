# Harness 与插件更新

[使用指南](../README.md) · [插件维护](plugin-maintenance.md) · [验证记录](validation-0.4.3.md)

## 官方更新

0.4.3 增加可恢复的官方更新事务，具体步骤、缓存策略和验证边界见[官方更新接续](official-update-flow.md)。

优先在“设置与说明 → 官方版本更新”中检查缓存包、预览并安装。启动器复用官方已下载的包，保存检查点、还原受管理补丁，调用官方安装器，验证安装结果后建立独立版本基线。可确认兼容且没有文件补丁的普通插件可自动恢复；purge 与其他无法确认兼容的插件暂停，旧材料保留。

直接在 Harness 内更新时，下一次经启动器点击启动会尝试使用官方缓存接续。更新时仍有活动文件补丁、用户文件出现未知改动、安装文件与官方包冲突时停止，不盲目回滚或重放旧补丁。启动器无法拦截官方更新器自行进行的立即重启。

“官方更新后原生启动”仍作为显式的原生验证入口，和自动接续共享已认证包清单。没有可用缓存时可提供官方安装包及 SHA-512，不另行重复下载。当前没有新官方版本可供真实升级验收；模拟测试不等于真实安装与窗口启动验收。

### Windows 0.2.1-rc.3 更新后缺少运行时

本机在原生配置下通过官方入口更新到 0.2.1-rc.3 后，`resources/runtime` 为空，启动报 `ENOENT ... office-skills/office/SKILL.md`。社区有[相同版本、相同症状的报告](https://github.com/deepseek-ai/deepseek-harness/discussions/10861)。这说明宿主运行时文件缺失；目前不能据此确定更新器内部的具体原因，也不能通过重新应用插件补丁修复。

遇到此错误先退出报错窗口，保留用户数据和更新缓存。可用同版本官方安装包修复安装；从缓存包手动恢复时，应先验证发布者签名、安装包校验和，以及包内主程序、`app.asar` 与已安装文件是否一致，再提取并验证完整 `resources/runtime`。仅补一个 `SKILL.md` 不足以修复 Python、Node 和其他运行时依赖。文件不匹配或目标目录已有无法解释的文件时应停止，避免混装版本。

启动器提供“设置与说明 → 官方运行时修复”，将上述核验及补齐流程做成显式预览操作，详见[运行时修复指南](runtime-repair.md)。启动前自动进行必需文件检查；官方更新器自行重启时不经过启动器的检查，失败后需打开启动器修复。不要删除账号、会话、插件记录或回滚材料来尝试解决运行时缺失。

## 插件自身更新

普通插件使用“更新与卸载”中的检查与升级预览。版本目标固定后保存维护检查点，安装后完成首次运行验证；共享依赖、其他插件及用户文件变化会导致暂停或拒绝。

purge 使用宿主补丁记录；升级包声明的宿主目标不同不再直接阻止安装。先保存检查点、还原旧补丁，再针对当前 Harness 安装与运行；新补丁必须匹配当前官方归档的版本和构建身份，并通过可逆记录校验。验证失败保留恢复入口。停用后的包、暂存目录和补丁同样校验。

因官方更新暂停、但尚无新版的普通插件，可以通过“预览重新验证并恢复”为同版本建立新记录。旧宿主的补丁和恢复材料保留，不作为新宿主的可写补丁重放。

手动从外部升级、相同版本号替换文件或同时更新宿主与插件，都会在内容与宿主身份检查中受到约束。不得通过清空数据、改版本号或强制覆盖快照来绕过冲突。

## 时间、空间与恢复

未变化的日常启动复用已验证内容缓存及目录检查点；变化后重新校验。内容对象按哈希去重。缓存清理仅处理复核后无引用且超过宽限期的对象，保留当前组合、方案、历史、备份及维护检查点。

跨 Harness 版本的自动三方文件补丁合并尚未实现；只对满足明确条件的无文件补丁插件接续。恢复使用已记录版本及现场证据；宿主变化或新增用户修改时停止。完整验证、下载、升级及维护不承诺 30 秒。
