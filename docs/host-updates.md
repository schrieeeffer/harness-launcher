# Harness 与插件更新

[使用指南](../README.md) · [插件维护](plugin-maintenance.md) · [验证记录](validation-0.4.0.md)

## 官方更新

更新会改变程序、ASAR 和依赖。启动器检测到身份变化时，报告可能发生官方更新或手动修改，停止重放不匹配的旧补丁并保留恢复材料；不将更新判为恶意行为。

官方更新前先退出 Harness，应用原生模式，再启动原生环境并使用官方更新入口。原生模式下更新后同样需要重新核验宿主，不能把旧版本基线用于新版本。

带插件更新可能留下新归档与旧解包目录混合状态。启动器会在下一次启动、切换、记录或恢复边界检查；它不能拦截官方更新按钮或更新器的自动重启。遇到提示应保留现场，停止旧补丁覆盖。兼容插件应在新版干净安装上重新记录。

## 插件自身更新

普通插件使用“更新与卸载”中的检查与升级预览。版本目标固定后保存维护检查点，安装后完成首次运行验证；共享依赖、其他插件及用户文件变化会导致暂停或拒绝。

purge 使用专用适配器；升级包声明的宿主目标必须匹配当前 Harness。停用后的包、暂存目录和补丁同样校验。不因只修改少数源文件就跳过生成目录的完整性证据。

手动从外部升级、相同版本号替换文件或同时更新宿主与插件，都会在内容与宿主身份检查中受到约束。不得通过清空数据、改版本号或强制覆盖快照来绕过冲突。

## 时间、空间与恢复

未变化的日常启动复用已验证内容缓存及目录检查点；变化后重新校验。内容对象按哈希去重。缓存清理仅处理复核后无引用且超过宽限期的对象，保留当前组合、方案、历史、备份及维护检查点。

跨 Harness 版本的自动三方补丁合并尚未实现。恢复使用已记录版本及现场证据；宿主变化或新增用户修改时停止。完整验证、下载、升级及维护不承诺 30 秒。
