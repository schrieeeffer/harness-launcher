## 结论与范围

普通插件和 purge 的更新、卸载、失败恢复、共享依赖保护及无引用回收通过隔离回归测试。启动器已真实重启到 0.4.0，便携 EXE 已启动随包 Python；六项前端资源与源码匹配，原配置未被重启改写。

日常和切换复测观察到完整窗口约 **20.8–35.1 秒**，符合本机“30 秒左右”的近似目标，但不能保证每次都在该范围。首次双插件切换有 **42.7 秒**的完整界面观察上界，明确保留为慢样本；没有把请求返回或进度满格当成窗口可用。

## 实际窗口计时

环境：现有 Windows x64 安装，Harness 0.2.0-rc.2，purge 1.1.71，whale 0.4.2。每轮先从原生应用菜单正常退出；全量测试、构建和浏览器截图未与计时并发运行。起点为提交启动请求，终点为原生窗口画面首次被观察到完整界面；随后点击菜单验证响应。

| 场景 | 后台请求完成（秒） | 完整窗口观察上界（秒） |
| --- | ---: | ---: |
| purge 日常启动 | 4.029 | 29.101 |
| purge → whale | 10.729 | 27.261 |
| whale 日常启动 | 1.583 | 20.761 |
| whale → purge + whale（首次慢样本） | 10.164 | 42.681 |
| purge + whale 日常复测 | 4.392 | 28.512 |
| purge + whale → whale 复测 | 10.374 | 25.884 |
| whale → purge + whale 复测 | 10.019 | 35.119 |

采样间隔为 2–3 秒，加上窗口枚举与捕获时间。首次慢样本的补充观察存在较宽间隔，因此表中值是上界，不是精确 ready 事件。双插件→purge 的另一次请求耗时 7.505 秒，30.203 秒看到了首页；该段未记录完整会话恢复时间，不拿它充当完整窗口达标数据。

额外试验过只通过环境变量启用 Node 编译缓存：请求 7.654 秒完成，但 52.110 秒内未观察到目标窗口，因此未采用该试验作为产品改动或验收成绩，随后恢复原环境。普通复测没有取消文件校验、共享依赖校验、宿主检查或事务回滚。

真实会话画面只用于本机观察，没有保存进仓库。公开截图来自隔离示例，不能当成第三方升级实证。

## 本机维护检查

- 更新检查：whale 0.4.2 当前无新版；purge 的包声明仓库查询到 1.1.78，声明目标 Harness 0.2.1-rc.2，与现有 0.2.0-rc.2 不同。执行路径会在建立检查点和改文件前拒绝；未在用户安装上升级 purge，也未执行官方 Harness 更新。
- 统一卸载预览可识别普通插件和外部本地 purge 来源。实际升级、卸载与回滚用隔离安装和受控包管理器边界完成，不删除用户真实插件来制作演示。
- 清理预览最初因历史重复引用做了重复文件探测，超过 5 分钟；加入每轮引用去重后，本机预览用时 68.557 秒，候选 68 个对象、188,163,101 字节（约 179.4 MiB）。本机只预览，未删除；隔离测试实际执行清理并验证引用内容保留。
- 查询、维护和引用遍历均按需运行。日常启动不运行网络更新检查或垃圾回收。首次检查、升级下载、维护恢复及缓存清理不承诺 30 秒。

## 分发与恢复限制

便携包自带 CPython 3.13.17 与 GUI 入口，仅支持 Windows x64；完整解压后双击 `Harness Launcher.exe`。官方 Harness 需预先安装。发布包不包含用户设置、令牌、会话、日志或第三方插件。主 EXE 当前未做商业代码签名。

恢复仍以已验证现场为前提。用户后来编辑、共享依赖变化、首次运行未封存或宿主更新时，可能必须先处理冲突；本版本不提供跨 Harness 版本的自动三方补丁迁移。详见[维护边界](plugin-maintenance.md)和[官方更新说明](host-updates.md)。
