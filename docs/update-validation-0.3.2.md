# 0.3.2 更新流程补充验证

[返回更新说明](host-updates.md) · [功能截图](feature-tour-0.3.2.md) · [架构与原理](architecture.md)

本次覆盖官方更新与插件更新的生命周期，不执行用户安装中的官方更新。更新器行为通过临时安装夹具中的文件替换、删除、移动和异常注入验证；真实窗口复测只使用原有 Harness 0.2.0-rc.2 与原有插件，不能据此认证新版 Harness 或插件兼容性。

## 场景与预期

| 场景 | 预期 |
| --- | --- |
| 原生或插件模式，仅下载更新 | 安装内容没变时保持可用，不改变基线。 |
| 官方 EXE 更新、ASAR 单独更新、同大小并恢复时间戳 | 检测实际内容变化，拒绝旧补丁；不创建新的可信旧基线。 |
| 活动 ASAR 已更新，旧暂存 ASAR 仍在 | 新活动归档优先，不能被旧副本掩盖。 |
| 相同内容被安装器重新复制 | 重新验证内容后接受，单凭时间或文件身份变化不拒绝。 |
| purge 更新助手已移走活动 app | 不启动不完整的安装，不删除助手的恢复目录。 |
| 包或依赖在校验后、创建进程前更新 | 启动前再次验证并拒绝执行未知新版代码，返回 `plugin_identity_changed`。 |
| 未启用的普通插件或 purge 仅更新包 | 原生文件完整时可继续原生；重新启用仍验证版本和内容。 |
| 插件安装期间发生官方更新 | 暂停安装或保存，保留会话，不把宿主变化登记为插件差异。 |
| 安装一个插件时，其他插件/依赖同版本替换 | 根据安装前内容引用识别变化并暂停，避免错误归属。 |
| 升级正常完成或取消未改动的安装 | 保留旧版历史或完整证据，结束时清除临时能力声明。 |
| 更新发生在提交、启动失败或撤销过程中 | 保留结构化错误和事务日志；按游标核验宿主后才撤销下一步。 |
| 归档移动后、游标落盘前崩溃 | 无外部改动时正常恢复；外部新归档出现时停止覆盖。 |

## 验证范围

`test_host_updates.py` 包含 31 个更新场景，另有安装记录、共享依赖、事务中断、缓存和状态契约回归。新会话使用 `recording-update-guards` 能力声明，领域测试要求宿主归档和其他插件的内容引用完整成套；旧程序不能忽略新保护。

设置页的新说明使用真实前端和隔离示例数据截图，在 1440、1080、390 px 视口检查页面及弹窗内容区，没有横向溢出或页面脚本异常。功能文档现包含 32 张截图；架构图和校验原理图已重新渲染并检查。

## 适用边界

启动器不拦截 Harness 内的更新按钮、第三方更新脚本或更新器自行重启，也不能把旧补丁自动迁移到新版宿主。直接替换官方 ASAR 的插件不能通过新的通用安装记录路径。未知变化需要恢复一致的安装或重新适配；不能靠清空缓存、修改版本号或覆盖旧快照解决。

旧版未结束的安装会话没有这些安装前证据，应先在原启动器版本完成或恢复。本轮没有删除应用目录、插件更新助手的恢复目录或历史回滚对象；可丢弃缓存的上限策略保持不变。
